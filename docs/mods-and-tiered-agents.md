# Claude Code Mods와 3계층 에이전트

공식 문서 확인 기준: 2026-10-18. 지원 범위는 실제 Claude Code 버전과 실행 환경에서 다시 확인한다. 이 문서는 기능과 설계를 설명하며 Mods 설치, 모델 변경, 자동 라우팅을 활성화하지 않는다.

## 공식 기능: Mods

Mods는 Claude Code 내부에서 실행되는 JavaScript·TypeScript 이벤트 핸들러를 포함한 플러그인이다. 프롬프트 제출, 도구 호출, UI 렌더링 등의 이벤트를 관찰하거나 변경하고 직접 처리할 수 있다. 지원되는 화면에서는 패널, 입력창 위 표시 영역, 버튼 등을 추가한다. 터미널은 v2.1.287 이상이 기준이며, UI 지원은 환경마다 다르다. Settings hooks는 설정 파일의 명령·HTTP 요청·프롬프트 방식이고, Skills는 지침, MCP는 도구 연결에 쓰인다. [공식 개요](https://code.claude.com/docs/en/plugins/mods/overview)

### 최소 구성과 이벤트 처리

공식 입문 예제의 구조는 다음과 같다. 파일 수가 고정된 규격은 아니다.

```text
my-mod/
├── .claude-plugin/plugin.json
└── hooks/
    ├── hooks.json
    └── register.js
```

`plugin.json`은 매니페스트이고, `hooks.json`의 `modules`는 코드 모듈 경로를 지정한다. 모듈이 내보내는 `register(on)`에서 이벤트를 등록한다. [작성 가이드](https://code.claude.com/docs/en/plugins/mods/create)

핸들러는 API 객체 `$`, 이벤트 `e`, 후속 처리 함수 `next`를 받는다.

| 패턴 | 동작 |
|---|---|
| 관찰 | `next(e)`로 기존 처리를 이어가며 정보를 기록 |
| 변경 | `next({ ...e, text: 새값 })`처럼 수정된 복사본 전달 |
| 직접 처리 | `next` 없이 이벤트에 맞는 결과를 반환해 후속 처리 중단 |

`e`는 깊게 동결되어 직접 수정하면 오류가 난다. 후속 처리 중단이 모든 모델 호출의 생략을 뜻하지는 않는다. 도구 실행 거부 사유도 모델에 도구 결과로 전달될 수 있다. [이벤트 처리](https://code.claude.com/docs/en/plugins/mods/events)

### 작성, 재로딩, 권한

내장 `plugin-authoring` 스킬로 필요한 기능을 자연어로 설명해 작성을 요청할 수 있다. `--plugin-dir` 개발 디렉터리는 변경 시 재로딩되며, Claude가 자신의 턴에서 저장한 변경은 턴 종료 시 반영된다. `claude plugin validate`는 매니페스트와 모듈의 정적 분석 결과를 보고한다. 검증 통과는 보안 인증이 아니다. [작성·검증 안내](https://code.claude.com/docs/en/plugins/mods/create)

Mods는 사용자 권한으로 실행되고 별도 샌드박스로 격리되지 않는다. 파일·프로세스·네트워크 접근을 검토해야 한다. `--safe-mode`는 설치한 Mods 외 다른 사용자 커스터마이징도 비활성화하며 내장 Mods까지 모두 중단하지는 않는다. [권한과 비활성화 범위](https://code.claude.com/docs/en/plugins/mods/overview)

## 사용자 정의 설계: Mods 활용

| 설계 예시 | 구현·검증할 부분 |
|---|---|
| Git·컨텍스트 상태 표시 | 수집 정보와 갱신 시점 |
| 도구 실행 타임라인·에이전트 관제 | 실패·취소·누락 상태까지 수집 |
| 화면 마스킹 | 표시 대상과 원본 처리 범위; 로그·파일·네트워크 보호와 구분 |
| 위험 명령 확인·파일 충돌 경고 | 탐지 범위, 우회·누락, 세션 간 상태 공유 |
| 다이어그램·이슈 트래커 연동 | 렌더링 구현, 인증, 외부 쓰기 승인 |

이 표는 FEF에 설치된 기능 목록이 아니다. API가 제공하는 확장 수단과 개별 구현을 구분한다. 공식 샘플인 `token-weather`, `blast-radius`도 기본 활성화 기능이 아니며 지원 보장 없이 제공되는 예제다. [공식 샘플 안내](https://code.claude.com/docs/en/plugins/mods/overview)

## 공식 기능: 서브에이전트와 캐싱

Claude Code 서브에이전트는 독립된 컨텍스트에서 작업하며 역할별 지침·도구·모델을 설정할 수 있다. 독립 컨텍스트가 파일시스템 격리를 뜻하지 않으며, 모든 도구 출력이 자동으로 Haiku를 거치지도 않는다. [서브에이전트](https://code.claude.com/docs/en/sub-agents)

프롬프트 캐싱은 반복되는 접두부를 재사용하는 별도 기능이다. 캐시 적중 조건, 최소 길이, 유효기간, 쓰기·읽기 요금을 고려한다. 고정 지침 배치만으로 캐시 적중을 보장할 수 없고 캐시는 컨텍스트 점유를 제거하지 않는다. [프롬프트 캐싱](https://platform.claude.com/docs/en/build-with-claude/prompt-caching)

## 사용자 정의 설계: 3계층 위임

다음은 역할 분담 예시이며 Claude Code의 기본 라우팅 규격이 아니다.

| 계층 | 작업 예시 | 반환할 근거 |
|---|---|---|
| 탐색·정리 | 파일·사용처 조사, 지정 로그 분석 | 결론, 파일·줄, 오류, 미확인 사항 |
| 구현·실행 | 코드 수정, 테스트, 실패 분석 | 변경 내용, 실행 명령·작업 위치·종료 상태 |
| 판단·검토 | 설계 판단, 복잡한 실패 분석, 독립 검토 | 판단 근거, 남은 위험, 수정 권고 |

모델은 작업 난이도, 도구 사용 능력, 비용, 검증 결과와 호스트 지원 범위에 맞춰 선택한다. 항상 가장 저렴한 모델부터 시작하거나 모든 작업을 세 계층에 통과시킬 필요는 없다. 이 예시는 기존 [Adaptive Effort](adaptive-effort.md)의 날짜가 명시된 L0–L3 선호도나 리뷰어 정의를 교체하지 않는다.

요약 길이와 승격 기준도 사용자 정의다. 고정 요약 길이, 자기평가 신뢰도 임계값, 정해진 실패 횟수가 공식 자동 승격 규칙은 아니다. 요약에는 실패 증거와 미검증 사항을 남기고 원본에 다시 접근할 수 있게 한다. 테스트 실패 시 환경·권한·요구사항 문제부터 구분한다. 실제 모델 변경은 호스트의 기능과 사용자 권한에 따른다.

### 효과 평가

위임은 메인 컨텍스트의 정보량을 줄일 수 있지만, 설명·요약·검토·재시도 비용을 추가한다. 동일 작업의 성공률, 회귀 결과, 전체 호출 비용, 캐시 사용, 재시도, 완료 시간을 함께 측정한다. 모델 변경 효과와 캐싱 효과를 분리하고, 전체 컴퓨팅 비용을 주장하려면 실행 환경 비용도 포함한다. 특정 절감률과 품질 유지는 실측 없이 보장하지 않는다. [공식 비용·성능 최적화 가이드](https://platform.claude.com/docs/en/about-claude/models/optimizing-for-cost-and-intelligence)

FEF는 이 문서의 3계층 자동 라우터나 도구 출력 압축기를 제공하지 않는다. 실제 도입 평가는 [측정 프로토콜](mod-evaluation-metrics.md)과 [저장소 자체 점수표](mod-evaluation-scorecard.md)를 참고한다. 해당 점수 기준은 공식 벤치마크가 아니다.
