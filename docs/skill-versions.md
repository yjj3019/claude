Plugin releases and skill interface versions have different scopes. Neither
mechanism automatically selects a model or grants execution permissions.

## Updating and checking a version

- Patch: compatible correction or clarification. Minor: compatible capability.
  Major: incompatible invocation, required input, output or operational obligations.
- Update an owned skill's canonical version when its interface changes; record the
  actual change and compatibility impact. Do not renumber unrelated skills.
- Any native payload change needs an appropriate plugin version, regeneration with
  `python scripts/build_plugin.py` and a subsequent `--check`.
- Hosts cache/update the plugin as one unit. `metadata.version` is descriptive,
  not a per-skill package manager, migration, dependency resolver or version lock.
  Pin an inspected artifact/commit and compare installed SKILL.md bytes when exact
  versions matter. Existing caches need an explicit update and a new session.
- Standalone `--check` compares source and installed bytes. `.fef-manifest.json`
  `version: 1` and verification `version: 1` are schemas, not skill SemVer.
  Do not migrate user data just to display a version.

An uncommitted version field does not imply a public release, tag or remote update.
