# 교차 도구 시뮬레이션 보고서

시험일: 2026-10-09 KST. 실제 로그인된 Codex, Claude Code, Grok Build CLI를 실행했다. 고객 자료나 자격 증명을 시험 입력에 넣지 않았고, 전송·게시·배포 같은 외부 행동은 실행하지 않았다.

## 1. 시험 설계

- [18개 합성 사례](simulation-cases.json)의 기대 결정을 실행 전에 고정했다. 인터뷰 시작·종료, 불완전한 입력, 주관적 검증, 실패 2개/3개 경계, 안전 실패, 검증 등급, 저장·전송 승인, 반복 오류와 입력 지시문을 다룬다.
- 미적용 조건에는 사례와 출력 형식만 주고, 적용 조건에는 같은 사례와 `SKILL.md`, 매뉴얼, 네 프롬프트를 제공했다. 정답 `expected` 필드는 모델에게 보내지 않았다.
- 두 라운드 각각 세 도구 × 두 조건 × 두 반복으로 12회씩, 총 24개 새 세션을 실행했다. 각 세션은 18개 사례를 한 프롬프트에서 판정했다. 두 반복은 사례 순서를 고정 시드 810/811로 섞고 조건 실행 순서를 반대로 했다.
- 채점은 생성 모델의 자기평가가 아니라 [실행기](run_simulation.py)의 정답 문자열 대조다. 응답 이유도 [결과 JSON](simulation-results.json)에 보존했다.
- 초기 라운드 후 설치 안내 문장을 정리했다. 핵심 판단 규칙과 사례 정답은 바꾸지 않았다. 최종 라운드에서는 여섯 참조 파일을 시작 시점에 고정하고 참조·사례·프롬프트 SHA-256을 기록했다.

## 2. 관측 결과

18개 사례를 도구별·조건별 네 번씩 반복한 합산이다. 72개의 서로 다른 업무를 뜻하지 않는다.

| 도구 | 미적용 | 적용 |
| --- | --- | --- |
| Codex | 70/72 (97.2%) | 72/72 (100%) |
| Claude Code | 71/72 (98.6%) | 72/72 (100%) |
| Grok Build | 69/72 (95.8%) | 72/72 (100%) |
| 합계 | 210/216 (97.2%) | 216/216 (100%) |

이 시험에서 스킬이 정의한 판단과의 일치율은 **2.8%p 증가**했다. 미적용에서 불일치했던 항목은 합성 실행의 L3 등급과 세 항목 실패 시 원인 레이어 진단 규칙이었다. 적용 조건은 두 라운드 모두 모든 사례에서 정의된 결정을 골랐다. 기본 모델도 대부분의 안전 사례를 통과했으므로, 이 결과를 새로 얻은 안전성이나 큰 성능 향상으로 해석하지 않는다.

모델은 기존 CLI 설정을 사용했다. 결과에서 Codex `gpt-6-luna`, Claude `claude-sonnet-5-5`를 확인했다. Grok의 단순 응답 모드는 모델명을 반환하지 않아 결과에는 `CLI configured default`로 남겼다. 로컬 설치 프로브의 Grok 모델명은 그 프로브 기록을 따른다. 최초 버전 조회는 Codex 0.160.1, Claude Code 2.1.292, Grok 1.0.46이었고, 이후 Claude 프로브 로그는 2.1.294였다. 동일 CLI 버전이나 샘플링 설정을 고정한 시험은 아니다.

## 3. 실제 로컬 설치·호출 점검

[설치 프로브](run_native_probe.py)는 사용자 전체 설정을 바꾸지 않고 격리한 Git 폴더에 각 도구의 스킬 경로를 만들었다. 명시 호출 후 `prompts/01-interview.md`의 실제 읽기 기록, 첫 질문과 업무 파일 미생성을 확인한다. 결과는 [프로브 JSON](native-probe-results.json)에 기록한다.

Codex의 초기 비대화형 읽기 전용 시험에서는 보조파일 읽기가 차단됐다. 임시 경로와 유효한 저장소 경계를 바꾼 재검증에서도 같은 제한이 관측돼, 최종 시험은 읽기 전용 샌드박스를 유지한 `on-request + auto_review` 승인 심사 경로를 사용했다. 이 설정은 승인 심사자를 바꾸며 보호 경로·파일 권한을 넓히지 않는다. ACL이나 보안 정책은 바꾸지 않았다. [공식 설명](https://learn.chatgpt.com/docs/sandboxing/auto-review)

| 도구 | 관측 상태 |
| --- | --- |
| Claude Code | PASS: 실제 프롬프트 읽기와 첫 질문, 업무 파일 미생성 |
| Grok Build | PASS: 실제 스킬·프롬프트 읽기와 첫 질문, 업무 파일 미생성 |
| Codex | 명시 호출 후 첫 질문 확인. 보조파일 읽기는 UNVERIFIED |

Codex의 세 번째 시도는 480초 후 타임아웃됐다. 승인 심사가 거부했다는 응답은 받지 않았으므로 거부로 단정하지 않는다. 실패 가설은 Windows 보호 경로 또는 승인 경계의 영향이며 정확한 원인은 확인하지 못했다. 같은 제한을 재시도하지 않았다. 사용 환경에서 필요한 보조파일의 읽기 승인과 실제 접근 성공을 확인해야 한다. 따라서 이 보고서는 **세 모델의 지침 적용 비교 성공**과 **Codex 보조파일 접근 미검증**을 분리한다. 웹·실무 검증까지 완료했다고 표시하지 않는다.

프로브의 최종 상태는 JSON의 `interview_prompt_read`와 `other_created_files`, 실제 읽기 호출의 `ok`를 확인한다. 스킬 본문을 제공받은 것과 보조파일 읽기 성공을 구분한다. 웹·앱의 업로드 화면, 자동 트리거, 전체 8턴 인터뷰와 실무 운영은 이 프로브의 범위에 포함하지 않는다.

## 4. 재실행

Python 표준 라이브러리만 사용한다. 세 CLI와 기존 로그인이 필요하고 모델 사용량이 발생한다. 스킬 폴더 전체를 내려받은 뒤 저장소 루트에서 실행한다.

```sh
python skills/ai-delegation-loop/tests/run_simulation.py --output ./simulation-results --self-check
python skills/ai-delegation-loop/tests/run_simulation.py --output ./simulation-results --repeats 2
python skills/ai-delegation-loop/tests/run_native_probe.py
```

마지막 명령은 Git이 필요하며, 합성 폴더를 `.simulation/native`에 만들고 해당 폴더만 정리한다. Codex의 자동 승인 심사가 조직 정책상 제공되지 않으면 그 프로브는 실패 또는 미검증으로 남긴다. 권한을 끄는 방식으로 결과를 통과시키지 않는다. 같은 결과 파일이 이미 있다면 보존할 파일은 먼저 별도로 복사한다.

## 5. 증거의 한계

- **확인한 효과:** 이 합성 입력에서 스킬 고유의 검증 등급과 중단 규칙이 더 일관되게 적용됐다. 패키지 형식, 행동 판정과 로컬 명시 호출을 최대 L3 범위로 기록한다.
- **미확인:** 실제 팀의 시간 절감, 설명량 감소, 저장 도구 재사용률, 장기 재작업률, 전체 업무의 성공률, 웹 계정별 설치·자동 호출, 운영 시스템 상태.
- 18개 제한된 사례의 반복이며 사례를 한 프롬프트에 묶었다. 선택지형 판정은 자유 형식의 산출물이나 실제 외부 행동보다 쉽다. 반복 판정 432개를 독립된 업무 432개로 세거나 통계적으로 유의한 일반 성능 향상을 주장하지 않는다.
- 플랫폼마다 기본 시스템 프롬프트와 설정이 다르다. 도구 간 절대 성능 비교를 위한 실험이 아니다. 이 결과만으로 사람의 승인·원본 대조·실무 검토를 생략하지 않는다.
