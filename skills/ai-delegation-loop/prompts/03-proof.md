# 프롬프트 3 — 실패할 수 있는 검증 항목 만들기

```text
[job-name]/SKILL.md의 “완료의 정의”에 이 업무 전용 검증 항목 5~10개를 추가해라.

각 항목은:
- 참·거짓 또는 확인 불가로 판정할 수 있어야 한다.
- 네가 산출물에서 “괜찮아 보인다”고 판단하는 것만으로 통과할 수 없어야 한다.
- 원본 파일, 승인된 참조 파일, 실제 링크, 테스트, 인용문, 개수, 렌더링 캡처 등 증거를 지정해야 한다.
- 실패했을 때 어떤 조치를 할지 정해야 한다.
- 해당 업무에 맞고 개인정보나 비밀정보를 불필요하게 복사하지 않아야 한다.

“명확함”, “전문적임”, “고품질”처럼 측정 기준이 없는 형용사는 단독 검증으로 쓰지 마라. 각 항목에 검증 절차와 근거 위치를 적어라. 불가능한 검증은 만들지 말고 필요한 입력을 표시해라.

앞으로 매 실행에서 결과를 전달하기 전에:
1. 각 항목을 실제로 검사해라.
2. 상태를 PASS, FAIL, UNVERIFIED, N/A 중 하나로 표시해라.
3. 상태마다 증거 위치와 검증 등급(L0~L4), 남은 불확실성을 한 줄로 적어라.
4. 실패 항목을 고쳤다면 전체 검증을 다시 실행해라. 미확인 항목을 PASS로 바꾸지 마라.
5. 첫 검사에서 세 항목 이상 실패하거나, 권한·개인정보·보안·대상 범위 검증 하나라도 실패하면 결과물 수정을 멈춰라. 실패 레이어와 원인을 설명하고 SKILL이나 툴박스 수정을 제안해라.
6. 외부에 영향을 주는 행동은 별도 명시 승인이 없으면 초안 단계에서 멈춰라.

파일을 직접 수정할 수 없으면 수정했다고 말하지 마라. 바뀐 전체 파일이나 정확한 패치를 출력하고 마스터 파일 저장 및 Project 사본 교체를 안내해라.
```
