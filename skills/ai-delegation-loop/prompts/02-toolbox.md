# 프롬프트 2 — 통과한 산출물을 툴박스에 저장하기

업무를 실제로 한 번 실행하고 담당자가 결과를 통과시킨 뒤에만 사용한다. 민감한 원본은 저장 전에 제거하거나 가명·합성값으로 바꾼다.

```text
방금 완료되고 담당자가 통과시킨 [스크립트 / 템플릿 / 규칙 파일 / 참조 자료]를 재사용 가능한 형태로 검토해라.

저장하기 전에:
- 실제로 통과한 결과인지, 초안이나 미승인 자료가 아닌지 확인해라.
- 비밀번호, API 키, 토큰, 개인정보, 고객 기밀, 불필요한 식별자가 없는지 확인해라. 하나라도 있으면 저장을 멈추고 안전한 대안을 제안해라.
- 재사용할 이유와 다음번에 달라질 부분을 식별해라.

저장 가능한 경우 모두 수행해라.
1. [job-name]/files/에 설명적인 안정된 파일명으로 저장해라. 파일명에 날짜나 버전 번호를 넣지 마라.
2. 고객명, 계정, 금액, 제품 등 업무마다 달라지는 값은 [대괄호 자리표시자]로 바꿔라. 채워진 예시가 필요하면 비민감·합성 데이터임을 표시하고, 실제 통과한 예시는 비식별화와 담당자 승인을 거친 뒤 [job-name]/examples/에 따로 저장해라.
3. [job-name]/SKILL.md의 해당 단계가 파일명을 직접 가리키도록 필요한 부분만 고쳐라. 언제 사용하고 언제 사용하지 않는지 적어라.
4. [job-name]/files/INDEX.md에 파일명, 용도, 저장일을 한 줄 추가해라. 확인할 수 없는 날짜를 추측하지 마라.
5. 바뀐 파일을 사람이 검토할 수 있게 전체 변경 diff 또는 변경 요약을 보여줘라.

저장할 대상이 아니거나 승인이 확인되지 않으면 쓰지 말고 이유를 말해라. 파일 접근 권한이 없으면 저장했다고 말하지 말고 파일 내용과 경로를 출력해라. 채팅 전용 도구에서는 사용자가 마스터에 저장한 뒤 Project의 이전 사본을 교체하도록 안내해라.

마지막으로 동일 업무를 처음부터 다시 실행해라. 실제 사용한 저장 파일, 새로 만든 파일, 재생성한 부분을 나눠 말하고, 다음 저장 후보는 승인 없이 추가하지 말고 제안만 해라. 외부 전송·게시·삭제·배포는 이 프롬프트만으로 실행하지 마라.
```
