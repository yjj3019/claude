# 프롬프트 4 — 실패 레이어 진단과 영구 수정

```text
결과물이 틀렸다.

업무: [job-name]
관찰된 문제: [무엇이 어떻게 틀렸는지, 실제 증거 위치]
실행 조건: [입력과 재현에 필요한 비민감 정보]

먼저 원인을 다음 레이어 중 하나 또는 여러 개로 분류해라.
- 프로세스: 단계가 빠졌거나 순서가 잘못됐거나 판단 규칙이 없었다.
- 툴박스: 저장 파일이 없거나 오래됐거나 잘못됐고, 기존 것을 다시 만들었다.
- 증명: 이 오류를 잡을 검증 항목이나 근거가 없었다.
- 외부 조건: 입력 자료·권한·시스템 상태가 바뀌었거나 확인할 수 없다.

각 분류와 근거를 짧게 설명해라. 원인이 불명확하면 추측하지 말고 UNVERIFIED로 표시해라.

그다음 승인된 범위에서만 가장 작은 영구 수정을 해라.
- 프로세스 실패면 SKILL.md의 관련 단계나 결정 규칙만 수정해라.
- 툴박스 실패면 해당 파일, 참조 위치, INDEX.md만 수정해라.
- 증명 실패면 완료 기준에 객관적 검증을 추가해라.
- 외부 조건이면 권위 있는 최신 입력을 확인하거나 담당자에게 넘겨라.

같은 실수가 두 번째라면 주의 문구만 보태지 말고 반복을 막는 규칙이나 검증을 추가해라. 전체 매뉴얼을 이유 없이 다시 쓰지 마라.

[job-name]/notes.md 맨 위에 날짜, 오류, 원인 레이어, 변경 파일, 재검증 결과를 기록해라. 날짜를 확인할 수 없으면 임의로 채우지 마라. 비민감 입력으로 동일한 작업을 다시 실행하고 수정 전후 차이와 각 검증의 증거를 보고해라. 재실행 전에 원래 작업의 외부 효과가 반복되지 않도록 해라.

파일을 직접 쓸 수 없으면 저장했다고 말하지 마라. 정확한 파일 경로와 새 내용을 출력하고, 사람이 마스터에 저장한 뒤 Project 사본을 교체하도록 안내해라. 메일·게시·삭제·결제·배포·권한 변경은 별도 명시 승인이 없으면 수행하지 마라.
```
