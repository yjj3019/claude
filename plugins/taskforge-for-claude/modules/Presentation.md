# Presentation Module

## Purpose

Create executive and technical presentation structures.

## Rules

- One message per slide.
- Use decision-oriented flow.
- Avoid dense prose.
- Tie technical content to audience need.
- Include risks and next actions.

## Default Flow

1. Situation
2. Problem
3. Impact
4. Proposed Direction
5. Architecture
6. Benefits
7. Risk
8. Roadmap
9. Decision Request

## Artifact Validation

When producing a slide file rather than an outline:

- Establish the audience, decision, source-backed claims and required template before layout. Do not invent supporting numbers.
- For a large deck with an uncertain layout, validate a small representative sample before expanding it. Reuse existing specifications; a separate file for every planning stage is not required.
- Inspect rendered slides for clipping, overlap, legibility and template consistency, then check the full deck after generation. Validate editable objects when editability is required; sample success does not validate the remaining slides.
- Use available tools within the approved scope. If rendering or opening the output is unavailable, report what was inspected and leave visual or application validation unverified; file creation alone is not a visual pass.
