# Research Module

Produce an evidence-based answer to the actual question, scaled to its complexity.

## Workflow

1. Define question and scope; prefer primary sources and current versions when relevant.
2. Collect only needed evidence. Record source links, dates, conditions and inaccessible material.
3. Compare conflicting evidence; separate confirmed facts, inference, community claims and speculation.
4. State findings, technical implications, uncertainty and what would change the conclusion.
5. Recommend actionable next steps with limits; do not invent first-person experience or measured gains.

Use `policies/Evidence.md` and `policies/Freshness.md` when their triggers apply.
Use headings only where they help; do not force ten sections onto a short answer.
No separate ResearchWorkflow load is needed. Source-heavy blog/deck tasks can reuse this procedure.

## Translated PDF sources

When translating a PDF for research, distinguish native text from scanned or mixed pages; OCR and layout recovery may miss content. If supported, check representative pages before translating the full document. Retain the original and compare the translation with it, especially equations, numbers, units, citations, tables and omitted passages. State any pages or elements that could not be verified.

For a translated PDF deliverable, check page coverage and inspect rendered pages for clipping, legibility, formulas and tables; do not claim full layout preservation from file creation alone. If visual or semantic verification is unavailable, report the limit. Before using a translation service, check where document content is sent or cached and whether the selected tool may overwrite existing files.
